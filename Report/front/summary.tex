\section{Executive Summary}
\label{sec:summary}

Karena Thailand, the fictional publisher in the course brief, wants a Player Intelligence System that protects game integrity, targets monetisation, understands player behaviour and improves retention. Our team (ML003) built five models that feed such a system and combined their predictions in one Kaggle submission, \texttt{sub\_v90f\_entropy\_dualhead\_md.csv}, which scored \textbf{0.87351 on the public leaderboard (1st place)}. Our probes showed that each task carries about one fifth of the public score, so every task matters. Figure~\ref{fig:summary-overview} shows how the tasks fit together and Table~\ref{tab:summary-master} lists the metric, method, validation result and business use of each one.

\paragraph{How we worked.} Three habits produced most of the score; they are the thread of Section~\ref{sec:methodology}. (i) \emph{Reverse-engineer the data-generating process first.} The data are synthetic, and every task had exact identities, uniform boxes, empty gaps or a mixture structure that a generic model cannot see. Finding them gave larger gains than any tuning. (ii) \emph{Turn the metric into a decision rule.} Binary F2 asks for a threshold near the 60\% flag rate, NMAE asks for a conditional quantile $q=1-1/(2p)$ instead of a mean, macro F1 asks for per-class decision weights, and F3 asks for a 10\% break-even probability. (iii) \emph{Validate without leakage and without trusting a single number.} Out-of-fold scores stayed consistent with the public leaderboard for Tasks 1 to 3, but not for Task 4, where the public images are harder than any random fold; there we used scene-grouped folds and one-change leaderboard probes.

\paragraph{Rule compliance.} The competition rules forbid using the test set for training-related purposes. In two rulings (15 and 16 November) the teaching assistant (TA) clarified that using test images or test predictions to choose a validation split, an augmentation or a class prior is not allowed, while priors, class weights and thresholds computed from the training set and applied to the test set as fixed values are allowed. Our final submission follows those rulings: every imputer, scaler, bin edge, calibration temperature, threshold and the Task 4 logit adjustment is computed from training data. We removed an earlier test-prediction-based prior correction and a test-rank threshold, and did not use the identifier leaks found in the first data release (Sections~\ref{sec:t1}, \ref{sec:t4} and \ref{sec:t5}).
